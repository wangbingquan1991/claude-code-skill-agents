# Skills — 可复用技能集合

## 模块概述

`skills/` 目录包含 4 个可复用的技能模块，为 AI Agent 提供从编码指导到记忆管理的多层次能力扩展。这些技能可独立使用，也可组合集成到更大的 Agent 系统中。

| 技能模块 | 定位 | 适用场景 |
|---------|------|---------|
| andrej-karpathy-skills | 编码哲学指导 | 代码编写、架构决策 |
| claude-mem | 记忆管理系统 | 长期上下文维护、知识积累 |
| claudecode-assistant-perspective | Agent 设计参考 | Agent 行为定义、Prompt 设计 |
| synology-spk-assistant-team | 团队协作模板 | 多 Agent 协作、任务分配 |

## andrej-karpathy-skills

### 四大原则

Andrej Karpathy 的编码哲学浓缩为四大核心原则：

| # | 原则 | 核心思想 |
|---|------|---------|
| 1 | **简洁至上** | 代码应尽可能简单，避免过度工程化 |
| 2 | **显式优于隐式** | 清晰的代码胜过聪明的代码 |
| 3 | **快速迭代** | 先让它工作，再让它优雅 |
| 4 | **最小依赖** | 减少外部依赖，保持可控性 |

### 三种集成方式

```
┌─────────────────────────────────────┐
│  方式 1: Claude Code (CLAUDE.md)     │
│  直接放入项目根目录，自动生效        │
├─────────────────────────────────────┤
│  方式 2: Cursor (.cursor/rules/)    │
│  作为 Cursor 规则文件加载           │
├─────────────────────────────────────┤
│  方式 3: Skill 目录                  │
│  通过 skills/ 目录结构化引用         │
└─────────────────────────────────────┘
```

## claude-mem

### 功能定位

claude-mem 是一个为 Claude Code 设计的**渐进式记忆管理系统**，解决 AI Agent 长期上下文丢失的问题。通过结构化的记忆层级和生命周期管理，让 Agent 具备持久化的知识积累能力。

### 6 层架构

```
┌─────────────────────────────────────┐
│  Layer 6: 用户界面层                 │
│  CLI 命令、交互提示                  │
├─────────────────────────────────────┤
│  Layer 5: 技能层 (12 个内置技能)     │
│  记忆操作、检索、维护                │
├─────────────────────────────────────┤
│  Layer 4: 生命周期层                 │
│  6 个生命周期钩子                    │
├─────────────────────────────────────┤
│  Layer 3: 策略层                     │
│  渐进式披露、优先级排序              │
├─────────────────────────────────────┤
│  Layer 2: 存储层                     │
│  文件系统、索引、版本控制            │
├─────────────────────────────────────┤
│  Layer 1: 核心层                     │
│  记忆模型、类型系统、校验            │
└─────────────────────────────────────┘
```

### 6 个生命周期钩子

| # | 钩子 | 触发时机 | 职责 |
|---|------|---------|------|
| 1 | `onInit` | 系统启动时 | 加载记忆索引、校验完整性 |
| 2 | `onRecall` | 检索记忆时 | 相关性匹配、优先级排序 |
| 3 | `onStore` | 存储记忆时 | 去重检测、格式标准化 |
| 4 | `onUpdate` | 更新记忆时 | 版本管理、冲突解决 |
| 5 | `onEvict` | 淘汰记忆时 | 重要性评估、归档处理 |
| 6 | `onSync` | 同步记忆时 | 跨会话同步、一致性保障 |

### 12 个内置技能

| 技能 | 功能 |
|------|------|
| `memory-store` | 创建新记忆条目 |
| `memory-recall` | 按条件检索记忆 |
| `memory-update` | 更新已有记忆 |
| `memory-delete` | 删除过期记忆 |
| `memory-search` | 语义搜索记忆库 |
| `memory-list` | 列出记忆概览 |
| `memory-export` | 导出记忆数据 |
| `memory-import` | 导入外部记忆 |
| `memory-merge` | 合并相似记忆 |
| `memory-tag` | 标签管理 |
| `memory-stats` | 统计分析 |
| `memory-maintain` | 维护与清理 |

### 渐进式披露策略

```
请求到达
    │
    ▼
Level 0: 仅返回记忆标题列表 (最小开销)
    │ 用户需要详情？
    ▼
Level 1: 返回摘要 + 关键标签
    │ 需要完整内容？
    ▼
Level 2: 返回完整记忆内容
    │ 需要关联上下文？
    ▼
Level 3: 返回记忆 + 关联记忆图谱
```

### 部署方式

- **本地模式**：记忆存储在项目 `.claude/` 目录
- **全局模式**：记忆存储在 `~/.claude-mem/` 共享目录
- **团队模式**：通过 Git 同步记忆库

## claudecode-assistant-perspective

### 7 心智模型

与 `agents/claudecode-expert` 共享相同的 7 个心智模型框架，但侧重于**如何运用这些模型指导 Agent 行为设计**：

| 模型 | 在 Perspective 中的应用 |
|------|------------------------|
| 代理优先 | 评估 Agent 自主性边界 |
| 测试驱动 | 定义行为验收标准 |
| 上下文管理 | 设计信息获取策略 |
| 渐进式披露 | 规划响应的信息密度 |
| 最小授权 | 限定工具使用范围 |
| 复利模式 | 设计知识积累机制 |
| 检查点驱动 | 插入验证与回滚点 |

### 诚实边界

定义 Agent 的诚实行为准则：
- **知之为知之** — 不确定时明确表达不确定性
- **能力边界** — 清楚声明能力范围外的请求
- **错误承认** — 发现错误立即纠正，不掩饰
- **推理透明** — 展示决策过程，而非仅给结论

### 参考资源结构

```
├── perspective.md          # 核心视角定义
└── skills/                 # 技能扩展
    └── assistant-design/   # Agent 设计指南
```

## 设计模式总结

### 渐进式披露 (Progressive Disclosure)

所有技能都采用分层信息展示：
- **首层**：标题 + 一句话摘要
- **二层**：核心要点列表
- **三层**：完整详细内容
- **四层**：示例与扩展资料

### 多层集成 (Multi-Layer Integration)

每个技能支持多种集成方式：
- CLAUDE.md — Claude Code 原生集成
- .cursor/rules — Cursor IDE 集成
- .agents/plugins — 插件系统集成
- 独立 CLI — 命令行独立使用

### 配置驱动 (Configuration-Driven)

行为通过配置文件控制，而非硬编码：
- 角色定义文件化
- 权限矩阵可配置
- 工作流模板化
- 阈值参数化
