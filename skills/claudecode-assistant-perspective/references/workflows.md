# 标准工作流详情
---

## 工作流 1: Skill 开发六步法

**适用场景**: 创建新的自定义 Skill

```
1. 需求分析
   ├── 识别触发场景（什么时候用这个 Skill？）
   ├── 定义输入输出格式
   └── 列出正反触发示例

2. 骨架搭建
   ├── 创建目录结构（SKILL.md + references + scripts）
   ├── 编写 Pushy Description（对抗 undertrigger）
   └── 定义 Progressive Disclosure 层级

3. 核心逻辑
   ├── 编写角色扮演规则
   ├── 提炼心智模型（3-7个）
   └── 设计标准工作流

4. 触发优化
   ├── 生成20个评估查询（8个应触发 + 8个不触发 + 4个边界情况）
   ├── 运行自动化优化循环
   └── 选择测试集上分数最高的描述

5. 测试迭代
   ├── 正向测试：确保应该触发的场景都能触发
   ├── 负向测试：确保不应该触发的场景不会误触发
   └── 边界测试：验证模糊场景下决策正确性

6. 精炼发布
   └── 应用双 Agent 精炼
```

## 工作流 2: 代码变更五阶段

**适用场景**: 任何涉及代码修改的任务

```
Phase 1: 探索（Explore Agent）
  └── 理解现有代码结构、依赖关系、模式
Phase 2: 计划（Planner Agent）
  └── 制定变更方案、风险评估、测试策略
Phase 3: 实现（TDD Guide Agent）
  └── 测试先行 → 最小实现 → 重构优化
Phase 4: 审查（Code Reviewer Agent）
  └── 质量检查 → 安全审计 → 问题修复
Phase 5: 验证（Build Error Resolver）
  └── 运行测试 → 构建验证 → 质量门限检查
```

## 工作流 3: 问题诊断六步走

**适用场景**: 调试 Skill/Agent 行为异常、工具调用失败等

```
1. 问题分类
   ├── Skill触发问题 → 检查description匹配度
   ├── Agent行为异常 → 审查提示词和工具授权
   ├── 上下文丢失 → 检查压缩策略和会话管理
   ├── 工具调用失败 → 检查权限、路径、参数格式
   └── 安全防护误报 → 检查触发规则和白名单

2. 信息收集
   ├── 会话摘要生成（提取关键上下文）
   ├── 工具调用日志分析（查看完整调用链）
   ├── 触发匹配度测试（运行评估查询集）
   └── 子Agent输出验证（对比预期与实际结果）

3. 假设验证
   ├── 针对每个可能的根因设计验证实验
   ├── 控制变量逐一排除
   └── 记录所有实验结果

4. 根因分析
   ├── 区分表象与根本原因
   ├── 分析系统性问题 vs 偶发问题
   └── 评估影响范围和优先级

5. 修复方案
   ├── 最小可行修复（不引入副作用）
   ├── 回归测试验证
   └── 预防措施文档化

6. 预防措施
   ├── 添加到常见问题知识库
   ├── 改进检查清单和监控
   └── 自动化测试覆盖此场景
```
