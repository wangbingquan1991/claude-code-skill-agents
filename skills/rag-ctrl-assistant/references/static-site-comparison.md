## 详细分析

### 自定义 build.py
- **最佳场景**：技术能力强，追求极致定制
- **核心优势**：完全可控，每一行代码都理解
- **核心劣势**：需要自行维护，没有社区支持
- **关键技术**：Python-Markdown, Jinja2, Pygments

### Quartz
- **最佳场景**：已有Obsidian仓库，想静态发布
- **核心优势**：原生支持Obsidian语法、双向链接、图谱视图、全文搜索
- **核心劣势**：依赖Node.js，主题定制需要了解JSX
- **关键插件**：Remark/Rehype插件链

### Hugo
- **最佳场景**：卡片数量 > 5000，追求极致构建速度
- **核心优势**：Go编译、毫秒级构建、丰富的文档主题
- **核心劣势**：Go模板语法学习曲线，Wiki链接需hack实现
- **关键配置**：render hooks实现 [[链接]] 语法

### MkDocs Material
- **最佳场景**：文档型知识库，偏好传统文档结构
- **核心优势**：内置搜索(lunr)、自动TOC、Python生态
- **核心劣势**：偏文档风格，Wiki功能需插件
- **关键插件**：mkdocstrings-autorefs（交叉引用）

### Astro
- **最佳场景**：现代化需求，混合React/Vue组件
- **核心优势**：最小JS输出、Pagefind零运维搜索
- **核心劣势**：需要前端框架知识
- **关键插件**：remark-wiki-links, astro-pagefind

## 选型决策矩阵

```
是否需要双向链接？
├─ 是 → Quartz 或 自定义build.py
└─ 否 → 需要极速构建？
         ├─ 是 → Hugo
         └─ 否 → 需要美观文档风格？
                  ├─ 是 → MkDocs Material
                  └─ 否 → Astro

是否已有Obsidian仓库？
├─ 是 → Quartz（首选）或 Obsidian Publish（愿意付费）
└─ 否 → 参上决策树

是否需要完全私有？
├─ 是 → 排除 Obsidian Publish
└─ 否 → 所有方案都支持

技术栈偏好？
├─ Python → 自定义build.py 或 MkDocs
├─ JavaScript → Quartz 或 Astro
├─ Go → Hugo
└─ 无偏好 → 自定义build.py（最灵活）
```

## 性能基准（1000张卡片）

| 方案 | 首次构建 | 增量构建 | 输出大小 | 搜索索引大小 |
|------|---------|---------|---------|------------|
| 自定义build.py | ~8s | ~0.5s | ~2MB | ~300KB |
| Quartz | ~12s | ~1s | ~3MB | ~400KB |
| Hugo | ~0.3s | ~0.05s | ~1.5MB | 外部(Lunr) |
| MkDocs | ~4s | ~0.3s | ~2.5MB | ~350KB |
| Astro | ~15s | ~0.8s | ~1MB | Pagefind |
